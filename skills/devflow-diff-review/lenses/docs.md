# docs — достоверность документации

Сверь описание поведения с реализацией, сначала на достоверность, затем на
необходимую полноту. Учитывай документацию API и пользовательских возможностей,
рабочие примеры, инструкции эксплуатации и связанные проектные документы,
которые изменение делает неверными или незавершёнными.

Выделяй сведения, без которых потребитель неправильно использует изменение:
предусловия, побочные эффекты, ошибки, требования к конкурентности и отмене,
новые параметры или изменившиеся контракты. Отсутствие пересказа очевидного
и стилистика прозы не требуют замечания. Объясняй последствия для конкретного
читателя, инструмента или агента, который опирается на документ.
